# Проверка обновления CRM — 6 сентября 2026

## Изменения

- Дозаказ использует общий `EquipmentGrid`: фотографии, категории, поиск и выбранное количество. Источник каталога соответствует форме нового заказа: активные категории.
- Полная корзина сохранена: количество, дневная/ночная смена, ручная цена за единицу, состояние и комплект. Начисление новой позиции начинается с её собственного времени выдачи.
- Добавлены «Паспорт ID (иностран)» и «Паспорт (иностран)» для клиента и доверенного лица.
- В заказах добавлены показатель и вкладка «Не возвращено». Это заказы с забытым комплектом или просроченной техникой, а не все текущие аренды. Из списка можно отметить фактический возврат аксессуаров.

## Найденные и исправленные ошибки

1. Аксессуары, забытые при частичном возврате, скрывались до закрытия всего заказа. Теперь отображаются и доступны к возврату в активном заказе.
2. Список заказов не передавал `manual_subtotal` в расчёт. Исправлены текущий итог, долг и предварительная сумма закрытия для ручных цен, включая ноль.
3. После 500 заказов старые долги и забытые аксессуары могли исчезнуть из фильтров. Загрузка читает все страницы с устойчивой сортировкой; ошибка запроса не маскируется пустым списком.
4. Поиск в заказах не использовал нормализацию имён и телефонов. Подключён существующий поиск с кириллицей/латиницей и номерами с кодом страны или без него; добавлен поиск по забытым аксессуарам.
5. База отклоняла существующий вариант «Паспорт с чехлом». Миграция сохраняет старые типы и разрешает этот вариант вместе с иностранными документами.
6. Некорректный JSON/структура возврата могли вызывать серверную ошибку. Добавлена проверка запроса до вызова атомарной функции и сообщение при сетевой ошибке в интерфейсе.

- `npm run typecheck`: пройден.
- `npm run build -- --webpack`: production-сборка пройдена. На этом Mac используется WASM SWC, так как нативный ARM-модуль не установлен.
- Браузер: поиск и категория, фотографии, 2 единицы по 170 000 = 340 000 UZS, комплект, состояние; добавление позиции с ночной ставкой 50 000 даёт 390 000 UZS.
- Узкое окно 680×863: ширина диалога и содержимого совпадает (648 px), горизонтального переполнения нет; каталог прокручивается отдельно, корзина остаётся достижимой.
- Обе иностранные опции проверены в форме клиента и форме заказа.
- Вкладка «Не возвращено» обнаружила 3 существующих заказа; выбор одного аксессуара включает кнопку подтверждения. Проверки в браузере проводились без сохранения изменений в рабочих записях.
- SQL-тест `scripts/check-document-types.sql` проверяет 7 типов и отклонение неизвестного значения через копию CHECK-ограничения во временной таблице, без изменения клиентов.

## Публикация и откат

- Сначала применяется расширяющая миграция с SQL-тестом в одной транзакции и ограничением ожидания блокировки 5 секунд. При ошибке транзакция откатывается.
- Push в `main` запускает существующий GitHub Action: сборка на VPS, затем перезапуск PM2.
- После деплоя проверяются ревизия Git, PM2, HTTP и интерфейс.
- Если новые основные страницы недоступны или расчёт расходится с проверенными сценариями: откатить коммит приложения через `git revert` и повторный деплой. Расширенное ограничение документов оставить: оно совместимо со старым кодом и не должно блокировать уже созданные иностранные документы.

## Ограничения и дальнейшая проверка

Это регрессионная проверка затронутых сценариев, не полная сертификация всей CRM. Реальные заказы не создавались и не закрывались для тестов; нагрузочные и полноценные end-to-end тесты записи требуют отдельной тестовой базы.

В каталоге замечена ночная ставка CANON R6 M2 = 50 UZS. Она может быть намеренной, поэтому данные автоматически не менялись; владельцу стоит проверить тариф. При дальнейшем росте базы фильтры и агрегаты списка лучше перенести на сервер, чтобы не загружать всю историю в браузер.
